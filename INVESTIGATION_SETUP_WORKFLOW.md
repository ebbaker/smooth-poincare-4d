# Investigation setup workflow

21 November 2026, America/New_York. Prepared for Edward Baker with OpenAI
assistance; actual setup model/effort not independently recorded.

Use this workflow for a new investigation or a branch of an existing one.
[AGENTS.md](AGENTS.md), [model routing](GPT_RESEARCH_MODEL_WORKFLOW.md),
[references](REFERENCE_WORKFLOW.md), [storage](LARGE_FILES.md) and
[chat history](tools/CHAT_HISTORY.md) govern their respective subjects.

## Establish scope and ownership

Read the parent navigation, existing sources and applicable instructions.
Identify the question, inherited evidence and unresolved premises before
writing a plan. Reuse existing identities and documents. Number new siblings
with the next available two-digit prefix; do not renumber existing branches.
Use an explicitly supplied destination directly rather than adding unnecessary
nesting. If ownership or scope cannot be resolved from the task, ask the author.

Creation of a scaffold activates no scientific work. Leave tasks accurately
marked ready and unactivated, reserved, or dependent on a named input.
Importing existing scientific material preserves its original status.

## Standard structure

| Location | Purpose |
| --- | --- |
| `README.md` | Question, current entry points and ownership |
| `DRAFT_HISTORY.md` | Short dated milestones with evidence links |
| `research-overview/OVERVIEW.md` | Background, objects, hypotheses and unresolved decisions |
| `research-plan/PLAN.md` | Sustained sequence of bounded B/E tasks |
| `research-progress/REGISTER.md` | Sole live status register for its declared task family |
| `research-progress/handoffs/` | Frozen requests, returns and model-change packets |
| `notes/` | Incremental derivations and research records |
| `brainstorm/notes/` | Consequential conceptual choices |
| `brainstorm/explanations/` | Explanations with source and status pointers |
| `numerics/` | Authorized code and small execution records |
| `reviews/` | Scoped assessments with reviewer and premise provenance |
| `references/README.md` | Canonical source ownership, branch uses and bibliography links |
| `chat-histories/` | Tool-managed public conversation records |
| `continuation-notes/` | Dated handoffs and self-contained continuation prompts |
| `manuscript/` | Existing or subsequently authorized editable manuscripts |

Keep empty working directories with short purpose READMEs. Do not invent
calculations, review outcomes or chat registrations to populate them. Existing
manuscripts may be imported with provenance; routine setup does not create a
new manuscript. Generated PDFs go under root `output/pdf/<branch>/`.

## Overview and research sequence

State the fixed objects, category/signature, orientation, chirality, conventions,
regularity, parameter domains, baseline and mathematical consequence sought.
Separate inherited assertions from newly checked claims. Explain which local,
perturbative or conditional inputs would need a global extension. Supporting
complex twistor geometry must name any missing Riemannian reality or global
bundle conditions before being used in the central program.

Classify tasks in advance under the model workflow. Give each a stable ID,
B/E type, recommended model and reason, readiness/dependencies, deliverable,
evidence standard, finite scope, completion condition and B escalation trigger.
Reserve E work whose mathematical route is undecided. Include a useful next
step after a failed estimate without presupposing that a route will succeed.

Default research continuation uses Astra/ultra leadership and authorized
bounded `gpt-6.2-sol`/ultra execution helpers. Preserve the author's selected
settings. An activated session continues through useful ready dependencies
and integration; one packet is not the session limit. Each helper gets a
fixed request and disjoint outputs. Only the designated lead updates shared
registers. Do not launch numerics as a side effect of folder creation.

## One register per task family

The branch register owns its tasks; the parent links it rather than copying
live rows. Re-read status before changing it. If a task family is split or a
register replaced, save a dated crosswalk and mark the former register
historical. Preserve issued requests, completed identities and failed evidence.
Plans and continuation notes are dated snapshots, not competing live registers.

## References, provenance and chat

Apply the reference workflow immediately. Choose one canonical source record,
link it across branches, cite exact passages at the point of use and record
what was actually inspected. Backfill only the sources needed for the current
work and label the extent honestly. Do not fabricate missing metadata.

Record author, assistance, date, actual available model/effort and input
versions in new research documents. Maintain authentic public chat history at
the appropriate shared or branch destination. Existing conversations retain
their unique registration and provenance unless relocation is requested.
Follow recorder locks, integrity checks and exact-source requirements.

## Finish setup

Write a continuation note with the status boundary, unresolved question,
routing table, exact inputs and register link, finite execution scope, and a
self-contained pasteable prompt for every new branch. Include sustained
in-scope continuation and bounded-helper authorization, while preserving
prerequisites and the author's selected model. Saving prompts activates no task.

Check navigation, input provenance, task ownership, dependency consistency,
model recommendations, file sizes and reference ownership. Record a concise
setup milestone, identify limitations, and leave scientific work unactivated.

## Collection selection

Direct smooth Poincaré investigations belong in `papers/investigations-1/`. Earlier coordinate and double-copy studies are preserved in `papers/initial-investigations/`. Number folders independently within each collection. Do not treat an initial study as direct conjecture research merely because it supplies background machinery. Preserve stable task IDs when folders move.
